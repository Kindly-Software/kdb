================================================================================
WHAT IT DOES (SPECIFICATION)
================================================================================

Detects computational capsule structs with cache-line misalignment.

TRIGGER:
  struct has #[repr(C, align(N))] attribute (capsule pattern)
  AND size % align != 0 (not cache-aligned)

EXAMPLE (BAD):
  #[repr(C, align(64))]
  struct BadCapsule {
      value: AtomicU64,  // 8 bytes (forgot padding!)
  }

COMPILER ERROR:
  error: capsule `BadCapsule` has size 8 bytes but alignment 64 bytes
    |
    = help: add 56 bytes padding to reach 64 bytes total
    = note: example:
    = note:     _padding: [u8; 56],

FIXED CODE:
  #[repr(C, align(64))]
  struct GoodCapsule {
      value: AtomicU64,
      _padding: [u8; 56],  // ← Added
  }

================================================================================
KEY IMPLEMENTATION DETAILS
================================================================================

LINT LEVEL: Deny (compile error, not warning)

DETECTION MECHANISM:
  1. Check if struct has #[repr(C, align(...))] → capsule pattern
  2. Use TyCtxt::layout_of() to get accurate size/alignment
  3. Check: size % align == 0
  4. If violated: emit diagnostic with exact padding suggestion

COMPUTATION:
  remainder = size % align
  padding_needed = align - remainder
  final_size = size + padding_needed

EXAMPLE CALCULATIONS:
  8B size, 64B align → 64 - 8 = 56B padding → 64B total ✓
  16B size, 128B align → 128 - 16 = 112B padding → 128B total ✓
  100B size, 64B align → 64 - 36 = 28B padding → 128B total ✓

WHY IT MATTERS:
  - False sharing: Multiple unaligned capsules share cache line
    * 7× 8B structs fit in 64B line → lock contention
    * Atomic operations: 30-50ns (vs <5ns for aligned)
    * Difference: 6-10× performance degradation

  - Cache thrashing: Unpredictable memory access patterns
    * Alignment violations defeat CPU prefetcher
    * 3-5× slowdown in real-world usage

  - SIMD safety: Some platforms require aligned SIMD loads
    * ARM/older x86 may crash on misaligned access
    * Rust should guarantee this, but lint enforces it

KNOWN LIMITATIONS
================================================================================

1. Attribute Detection
   Uses: format!("{:?}", attr).contains("align")
   Limitation: Works for 99% of cases, not robust AST parsing
   Workaround: Can improve with syn crate in future

2. Generic Types
   Limitation: layout_of() may fail for complex generics
   Workaround: Conservative (skip rather than false positive)
   Example: Generic<T> where T: ?Sized

3. External FFI Types
   Limitation: Non-power-of-2 alignments may exist
   Workaround: Use #[allow(clippy::...)] for FFI wrappers

4. Nested Structs
   Current: Only checks top-level struct alignment
   Future: Could recursively check field alignments
