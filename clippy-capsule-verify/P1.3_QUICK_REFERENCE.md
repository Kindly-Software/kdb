# P1.3 CAPSULE_INCORRECT_PADDING - Quick Reference

## What It Does

Detects padding fields with incorrect size calculations in computational capsules.

## Problem Examples

### Under-Padding (Most Common)
```rust
#[repr(C, align(64))]
struct BadCapsule {
    state: AtomicU64,      // 8 bytes
    _padding: [u8; 50],    // ❌ WRONG! Should be 56
}  // Total: 58 bytes → False sharing!
```

**Consequence**: 3-5× performance degradation from cache contention

### Over-Padding (Memory Waste)
```rust
#[repr(C, align(64))]
struct WastefulCapsule {
    state: AtomicU64,      // 8 bytes
    _padding: [u8; 120],   // ❌ WRONG! Should be 56, wastes 64 bytes
}  // Total: 128 bytes → Unnecessary memory waste
```

**Consequence**: Memory overhead, reduced cache efficiency

### Correct Padding
```rust
#[repr(C, align(64))]
struct GoodCapsule {
    state: AtomicU64,
    _padding: [u8; 56],    // ✅ CORRECT! (64 - 8 = 56)
}  // Total: 64 bytes → Perfect cache alignment
```

## Quick Fix Formula

```
required_padding = alignment - (size_of_fields % alignment)
```

### Examples

| Fields | Alignment | Calculation | Padding Needed |
|--------|-----------|-------------|----------------|
| 8B | 64B | 64 - (8 % 64) = 56 | `[u8; 56]` |
| 16B | 64B | 64 - (16 % 64) = 48 | `[u8; 48]` |
| 24B | 64B | 64 - (24 % 64) = 40 | `[u8; 40]` |
| 8B | 128B | 128 - (8 % 128) = 120 | `[u8; 120]` |
| 64B | 64B | 64 - (64 % 64) = 0 | No padding needed |

## Diagnostic Output

```
warning: capsule `BadCapsule` has incorrect padding: under-padding (current: 50 bytes, required: 56 bytes)
  --> src/example.rs:10:1
   |
10 | struct BadCapsule {
   | ^^^^^^^^^^^^^^^^^
   |
   = note: current padding field: `_padding` = 50 bytes
   = help: calculation: align=64, size_without_padding=8, required_padding=56
   = help: change `_padding` to: `_padding: [u8; 56]`
   = note: current total size: 58 bytes (should be 64 bytes)
```

## How to Fix

1. Read the diagnostic (it tells you exact padding needed)
2. Update the padding field size:
   ```rust
   - _padding: [u8; 50],  // Old (wrong)
   + _padding: [u8; 56],  // New (correct)
   ```
3. Recompile (warning should disappear)
4. Verify: `size_of::<YourCapsule>()` should equal alignment

## Padding Field Naming

The lint recognizes these patterns:
- `_padding` (preferred)
- `_pad` (alternate)
- `_pad1`, `_pad2`, etc. (numbered)
- `_padding_bytes`, `_pad_data`, etc. (prefixed)

**Not recognized**: `padding`, `pad` (missing underscore)

## Common Mistakes

### 1. Arithmetic Error
```rust
// Calculation: 64 - 8 = 56
_padding: [u8; 54],  // ❌ Wrong math!
_padding: [u8; 56],  // ✅ Correct
```

### 2. Wrong Alignment Reference
```rust
#[repr(C, align(128))]  // Note: 128B alignment!
struct Capsule {
    state: AtomicU64,
    _padding: [u8; 56],  // ❌ Using 64B alignment formula!
}
// Should be: [u8; 120] for 128B alignment
```

### 3. Forgot to Update After Adding Fields
```rust
#[repr(C, align(64))]
struct Capsule {
    state: AtomicU64,     // 8B
    counter: AtomicU64,   // 8B (newly added!)
    _padding: [u8; 56],   // ❌ Still using old padding for 8B!
}
// Should be: [u8; 48] for 16B of fields
```

## Integration with Other Lints

| Scenario | Lint Triggered |
|----------|----------------|
| No padding field at all | `CAPSULE_UNALIGNED_VIOLATION` (P0.2) |
| Padding field but wrong size | `CAPSULE_INCORRECT_PADDING` (P1.3) ← This lint |
| Missing verification derive | `MISSING_CAPSULE_VERIFICATION` (P1) |
| Non-atomic fields | `CAPSULE_NON_ATOMIC_FIELD` (P0.4) |

## Testing Your Capsule

```rust
#[cfg(test)]
mod tests {

    fn test_capsule_layout() {

    }

```

## Performance Impact

| Padding Status | Cache Behavior | Performance |
|----------------|----------------|-------------|
| **Correct (56B)** | Exclusive cache line | Baseline (1.0×) |
| **Under (50B)** | False sharing | 0.2-0.33× (3-5× slower) |
| **Over (120B)** | Wasted memory | ~1.0× (but uses 2× memory) |

## When to Disable

Rare cases where you might suppress this lint:

```rust
#[allow(clippy::capsule_incorrect_padding)]
#[repr(C, align(64))]
struct ExternalFFI {
    // Padding controlled by C library, not our choice
    _padding: [u8; 42],
}
```

**Note**: Only suppress if you have a documented reason. Incorrect padding causes real performance bugs.

## Quick Decision Tree

```
Is there a padding field?
├─ NO → Use CAPSULE_UNALIGNED_VIOLATION to fix
└─ YES
   └─ Is padding size correct?
      ├─ NO → This lint (P1.3) will catch it
      └─ YES → All good! ✓
```
