## Lint Specification

### Name
`clippy::capsule_memory_ordering`

### Level
**Allow** (opt-in, some use cases legitimately need Relaxed for performance)

### Trigger
Atomic operations using `Ordering::Relaxed`:
- `load(Ordering::Relaxed)`
- `store(value, Ordering::Relaxed)`
- `swap(value, Ordering::Relaxed)`
- `compare_exchange(..., Ordering::Relaxed, ...)`
- `fetch_add/sub/and/or/xor/max/min/nand(value, Ordering::Relaxed)`

### Recommendations

| Operation | Suggested Ordering | Rationale |
|-----------|-------------------|-----------|
| `load` | `Acquire` | Synchronize reads (see writes before this load) |
| `store` | `Release` | Synchronize writes (guarantee writes visible to others) |
| `swap` | `AcqRel` or `SeqCst` | Both read and write synchronization |
| `compare_exchange` | `SeqCst` | Critical section, full ordering guarantees |
| `fetch_*` | `AcqRel` | Read-modify-write needs both sync directions |

## Detection Strategy

1. **HIR Expression Analysis**: Uses `ExprKind::MethodCall` to detect atomic method calls
2. **Type Checking**: Verifies receiver type contains "Atomic" (AtomicU64, AtomicBool, etc.)
3. **Ordering Extraction**: Parses `QPath::Resolved` to extract Ordering variant from arguments
4. **Position Detection**: Different atomic ops have Ordering in different arg positions:
   - `load(ordering)` → args[0]
   - `store(val, ordering)` → args[1]
   - `compare_exchange(current, new, success, failure)` → args[2]

## Example Bad Patterns Detected

```rust
// BAD: Relaxed load (no synchronization)
let value = state.load(Ordering::Relaxed);  // ❌ Warning emitted

// BAD: Relaxed store (no synchronization)
state.store(42, Ordering::Relaxed);  // ❌ Warning emitted

// BAD: Relaxed compare_exchange (breaks coordination)
state.compare_exchange(
    old,
    new,
    Ordering::Relaxed,  // ❌ Warning emitted
    Ordering::Relaxed,
);
```

## Example Good Patterns (No Warning)

```rust
// GOOD: Acquire load (synchronize reads)
let value = state.load(Ordering::Acquire);  // ✓ No warning

// GOOD: Release store (synchronize writes)
state.store(42, Ordering::Release);  // ✓ No warning

// GOOD: SeqCst compare_exchange (full ordering)
state.compare_exchange(
    old,
    new,
    Ordering::SeqCst,  // ✓ No warning
    Ordering::SeqCst,
);
```

## Suppression

For intentional Relaxed use (e.g., non-coordinating metrics):

```rust
#[allow(clippy::capsule_memory_ordering)]
fn intentional_relaxed_counter(&self) -> u64 {
    // This is a non-coordinating counter (metrics only)
    // Relaxed is intentional for performance
    self.count.load(Ordering::Relaxed)
}
```

## Framework Compliance

### UCE34 Q10 (Tier Selection)
- **Why Memory Ordering Matters**: Relaxed breaks Chaos SeqCst/SWeMR lockfree guarantees
- **Performance Impact**: 3-10× latency spike when race detected and retry triggered
- **Correctness**: Acquire/Release provide happens-before relationship for coordination

### Chaos (Computational Capsule) Mandate
- **Lockfree Requirement**: Relaxed ordering defeats lockfree synchronization
- **SWeMR Pattern**: Single Writer, Multiple Readers requires Acquire/Release minimum
- **Generation Counters**: Relaxed breaks TOCTOU detection (load gen → load value → changed!)

### ASSUM Framework
- `#ASSUME_METHOD_CALL_EXTRACTION`: HIR `ExprKind::MethodCall` available for atomic ops
- `#ASSUME_ORDERING_ARG_ACCESSIBLE`: Ordering argument extractable from method args via QPath
- `#VERIFY_ORDERING_DETECTION`: UI tests validate correct/incorrect pattern detection

### B32 (Fair Benchmarking)
- **Performance Claims**: 3-10× latency spike documented in Chaos patterns
- **Race Condition**: Relaxed → stale reads → retry loops → 3-10× slowdown
- **Validation**: Proven in CircuitBreaker (9.8ns w/ Acquire vs 30-50ns w/ races)

## Known Limitations

1. **HIR-Level Analysis**: Cannot catch macro-generated code with Ordering::Relaxed
2. **Cross-Module Calls**: Only detects direct method calls, not wrapped functions
3. **Type Resolution**: Relies on type name containing "Atomic" (works for std types)
