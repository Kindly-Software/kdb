## Executive Summary

Implemented P1.3 CAPSULE_INCORRECT_PADDING lint to detect padding fields with incorrect size calculations. This lint catches subtle bugs where padding fields exist (appearing correct) but have wrong sizes, causing capsules to still be unaligned despite the padding field presence.

### Detection Algorithm

```rust
// 1. Find padding field(s) (name matches _padding, _pad, or _pad*)
// 2. Calculate struct size without padding field
// 3. Calculate required padding: align - (size_without_padding % align)
// 4. Compare actual padding array size vs required padding
// 5. Emit diagnostic if mismatch detected
```

### Examples Detected

**Bad (Under-padding)**:
```rust
#[repr(C, align(64))]
struct BadCapsule {
    state: AtomicU64,      // 8 bytes
    _padding: [u8; 50],    // WRONG! Should be 56 (64-8=56)
}  // Total: 58 bytes (not 64!) → Still unaligned!
```

**Good (Correct padding)**:
```rust
#[repr(C, align(64))]
struct GoodCapsule {
    state: AtomicU64,      // 8 bytes
    _padding: [u8; 56],    // CORRECT! (64-8=56)
}  // Total: 64 bytes ✓
```

**Over-padding**:
```rust
#[repr(C, align(64))]
struct WastesCapsule {
    state: AtomicU64,      // 8 bytes
    _padding: [u8; 120],   // WRONG! Should be 56, wastes 64 bytes
}  // Total: 128 bytes (over-padding, memory waste)
```

## Technical Details

### Padding Field Naming Conventions

Detected patterns:
- `_padding` (preferred, single padding field)
- `_pad` (alternate short form)
- `_pad1`, `_pad2`, etc. (numbered variants for multiple padding fields)
- `_padding1`, `_padding2`, etc. (numbered variants)

### Algorithm Breakdown

```rust
// Step 1: Get struct layout
let layout = cx.tcx.layout_of(typing_env.as_query_input(ty))?;
let total_size = layout.size.bytes();

// Step 2: Find and sum padding field sizes
let mut total_padding_size = 0u64;
for field in variant_data.fields() {
    if is_padding_field_name(field.ident.as_str()) {
        let field_layout = cx.tcx.layout_of(typing_env.as_query_input(field_ty))?;
        total_padding_size += field_layout.size.bytes();
    }
}

// Step 3: Calculate required padding
let size_without_padding = total_size - total_padding_size;
let remainder = size_without_padding % align;
let required_padding = if remainder == 0 { 0 } else { align - remainder };

// Step 4: Compare and emit diagnostic
if total_padding_size != required_padding {
    emit_diagnostic(/* ... */);
}
```

### Edge Cases Handled

1. **Multiple padding fields**: Sums all padding fields, validates total
2. **Already aligned**: Correctly handles remainder == 0 case (no padding needed)
3. **Over-padding**: Detects when padding exceeds required amount (memory waste)
4. **Under-padding**: Detects when padding is insufficient (false sharing risk)
5. **Complex layouts**: Works with multiple non-padding fields

## Why This Matters

### Problem Statement

Padding fields are added to ensure cache-aligned capsules, but incorrect calculations defeat the purpose:

1. **False positive safety**: Code looks correct (has padding field) but is actually broken
2. **Subtle bugs**: Under-padding causes false sharing (3-5× slowdown)
3. **Memory waste**: Over-padding wastes memory unnecessarily
4. **Review difficulty**: Manual review can't catch arithmetic errors in padding calculations

### Real-World Impact

**Before this lint**:
```rust
// Developer adds padding but makes arithmetic error
#[repr(C, align(64))]
struct BrokenCapsule {
    state: AtomicU64,      // 8 bytes
    counter: AtomicU64,    // 8 bytes
    _padding: [u8; 40],    // ERROR! Should be 48 (64-16=48)
}  // Total: 56 bytes → False sharing!

// Compiles without warning
// Runtime: 3-5× slowdown from cache contention
// Debugging: Hours to identify false sharing cause
```

**After this lint**:
```rust
// Same code triggers compile warning
warning: capsule `BrokenCapsule` has incorrect padding: under-padding
  = help: change `_padding` to: `_padding: [u8; 48]`
  = note: current total size: 56 bytes (should be 64 bytes)

// Developer fixes immediately:
#[repr(C, align(64))]
struct FixedCapsule {
    state: AtomicU64,
    counter: AtomicU64,
    _padding: [u8; 48],    // CORRECT!
}  // Total: 64 bytes ✓
```

**Result**: Compile-time detection prevents runtime performance bugs.
