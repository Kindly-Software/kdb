EXAMPLE USAGE:

// Prepare read operation
let mut buffer = vec![0u8; 4096];
ring.prep_read(fd, &mut buffer, offset, user_data_1)?;

// Prepare write (depends on read)
ring.set_link_flag()?;
ring.prep_write(fd, &buffer, offset, user_data_2)?;

// Submit both (kernel will execute atomically)
ring.submit(2, 0)?;

// Harvest completions
while let Some(cqe) = ring.peek_cqe()? {
    match cqe.user_data {
        user_data_1 => println!("Read complete: {} bytes", cqe.res),
        user_data_2 => println!("Write complete: {} bytes", cqe.res),
        _ => {}
    }
    ring.advance_cqe()?;
}

KNOWN LIMITATIONS & ROADMAP:

Limitation 1: Flag Setting API
  Current: set_*_flag() methods stub (require SQE mutation capability)
  Workaround: Set flags inline during prep_* calls (future API)
  Fix Timeline: Phase Q3.8 (requires IoUringCapsule::set_sqe_flag() extension)
  Impact: Low (99% of use cases don't need flag modification)

Limitation 2: Simplified Signatures
  Current: Accept/Connect/Openat missing sockaddr/pathname pointers
  Workaround: Production code uses native pointers directly
  Fix Timeline: Phase Q3.9 (add generic pointer support)
  Impact: Medium (requires careful lifetime management)

Limitation 3: SQPOLL Support
  Current: Uses io_uring_enter syscall for submission
  Future: Support SQPOLL thread for syscall-free submissions
  Benefit: Eliminates syscall overhead (already <1μs)
  Fix Timeline: Phase Q4 (optional optimization)
