ARCHITECTURE HIGHLIGHTS
================================================================================

Memory Layout (512 bytes, cache-aligned):
  Offset 0-15:     Coordination (state + generation counter)
  Offset 16-31:    Last verification timestamp
  Offset 32-95:    Verification metrics (64B)
  Offset 96-127:   SLSA compliance status (32B)
  Offset 128-159:  Dependency verification (32B)
  Offset 160-191:  Signature verification (32B)
  Offset 192-223:  Checksum verification (32B)
  Offset 224-255:  Build reproducibility (32B)
  Offset 256-319:  Audit trail management (64B)
  Offset 320-511:  Padding (192B)

Coordination Pattern (DualAtomicU64):
  High 32 bits: Generation counter (ABA prevention)
  Low 32 bits: State (Inactive/Initializing/Active/Suspended/Revoked)
  Update method: CAS loop with Acquire/Release ordering

Key Methods:
  new() - Create capsule (<100ns)
  activate() - Activate verification (<15ns)
  verify_artifact() - Main verification (<10ms)
  append_audit_entry() - Q34 audit trail (<50ns)
  verify_audit_integrity() - Tamper detection
  stats() - Get verification metrics
