MISSION CRITICAL PROBLEM
═══════════════════════════════════════════════════════════════════════════════

ConcurrentMapU64 specialized u64 key map has mixed workload regression:

  get:     23.3ns → 4.62ns  ✅ 5.05× speedup
  insert:  484ns → 215ns    ✅ 2.25× speedup
  remove:  ? → ?            ✅ Expected 15× speedup
  mixed:   23.1ns → 41.0ns  ❌ 0.56× REGRESSION (CRITICAL)

ROOT CAUSE: Reserved key checks (0 and u64::MAX) cause branch misprediction
  - Each operation: if key == 0 || key == MAX → 10-15ns branch mispredict
  - Impact on mixed workload: 50% get × 15ns = major bottleneck

═══════════════════════════════════════════════════════════════════════════════
BREAKTHROUGH SOLUTION: GENERATION COUNTER APPROACH
═══════════════════════════════════════════════════════════════════════════════

ARCHITECTURAL CHANGE:

  Before: Use reserved keys (0=empty, MAX=tombstone) to mark bucket state
          → Requires branch check: if (key == EMPTY || key == TOMBSTONE)
          → 10-15ns branch misprediction per operation

  After:  Use generation counter to track bucket state
          → generation == 0: bucket EMPTY (no branch check needed)
          → generation > 0: bucket OCCUPIED (no branch check needed)
          → Supports FULL u64 range (0 and MAX now valid!)

KEY INSIGHT: Branch misprediction dominates mixed workload timing
