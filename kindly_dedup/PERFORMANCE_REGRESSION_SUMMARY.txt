================================================================================
WHY POLLING DOMINATES
================================================================================

1. Worker threads finish work FAST:
   - 10K docs, 1 batch = signature computation ~2ms
   - Main thread spawned workers at t=0.5ms
   - Workers done at t=2.5ms

2. Main thread sleeps LONG:
   - Each polling iteration: 10ms sleep
   - No early-exit mechanism before next check
   - Even if work finishes after 2ms, main sleeps until 10ms mark
   - Wasted cycles: 8ms per iteration

3. Multiple iterations add up:
   - 6 iterations × 10ms = 60ms
   - Actual worker execution: ~2ms
   - Overhead ratio: 60ms / 2ms = 30× wasted sleeping!

4. Parallelism can't reduce polling overhead:
   - Polling is sequential (main thread only)
   - Adding worker threads doesn't reduce 60ms sleep
   - It only slightly speeds up workers (which are already fast)
