│  Hopscotch Hashing:                                                             │
│  ├─ H=32 neighborhood (single cache line, 64 bytes)                            │

│  ├─ AtomicU64 key_hash (0 = empty, u64::MAX = tombstone)                       │

│  ├─ AtomicPtr<K> key_ptr (heap-allocated key)                                  │
│  └─ AtomicPtr<V> value_ptr (heap-allocated value)                              │
│                                                                                 │
│  Performance:                                                                   │
│  ├─ Insert: <200ns (CAS + Box allocation)                                      │
│  ├─ Get:    <100ns (atomic load + neighborhood scan)                           │
│  ├─ Remove: <150ns (CAS + generation bump + Box dealloc)                       │
│  ├─ Concurrent throughput: 5M+ ops/sec (8 threads)                             │
│  └─ Scale: Efficient up to 10M+ entries                                        │
│                                                                                 │
│  Why Hopscotch over Chaining?                                                  │
│  ├─ Cache-friendly: H=32 fits in single cache line (64B)                       │
│  ├─ Bounded displacement: Max H=32 hops (vs unbounded chaining)                │
│  ├─ Better locality: Neighboring slots stay in same cache line                 │
│  └─ SIMD-friendly: Neighborhood scan vectorizable (4× speedup)                 │
│                                                                                 │
│  ASSUM Safety:                                                                  │
│  ├─ #ASSUME_HOPSCOTCH_BOUNDED: H=32 sufficient at <90% load factor            │
│  ├─ #VERIFY_HOPSCOTCH_BOUNDED: Property tests validate >99.9% success         │
│  ├─ #ASSUME_ATOMIC_NEIGHBORHOOD: AtomicU32 bitmap prevents races              │
