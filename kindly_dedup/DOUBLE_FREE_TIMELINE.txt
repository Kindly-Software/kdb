================================================================================
THE BUG IN 3 SENTENCES
================================================================================

1. Main thread creates PairsIterator (line 397), which owns Vec<Arc<LockfreeList>>
   containing 1.27M entries (current_snapshot field).

2. Main thread waits for 16 workers to finish (line 466-469), but iterator is
   still alive (local variable on stack), so Arc references are valid.

3. Function returns (line 486), dropping iterator and its 1.27M Arc references
   concurrently while workers are STILL ACCESSING data via chunks, causing
   double-free when Arc destructors run simultaneously.

================================================================================
KEY INSIGHT
================================================================================

The bug is NOT about memory growth (that's a symptom).
The bug IS about iterator lifetime vs worker thread lifetime (root cause).

All 3 failed attempts tried to reduce memory (symptoms) but didn't address
the lifetime mismatch (root cause).

Fix: Ensure producer thread owns data and joins BEFORE dropping Arc references.
