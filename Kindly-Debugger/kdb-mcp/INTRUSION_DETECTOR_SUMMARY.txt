                            API REFERENCE
================================================================================

CORE METHODS:

  pub fn check_ip(&self, ip: &str) -> Result<(), IntrusionError>
    Check if IP is currently blocked. Returns Ok(()) if allowed,
    Err if blocked. Latency: ~105ns

  pub fn record_failure(&self, ip: &str)
    Record failed authentication attempt. Sets all 4 Bloom bits.
    Latency: ~105ns

  pub fn is_blocked(&self, ip: &str) -> bool
    Convenience method. Returns true if blocked.
    Latency: ~105ns

  pub fn unblock_ip(&self, ip: &str)
    Clear bits for manual appeal. Warning: may cause false negatives
    if bits overlap with other IPs.
    Latency: ~105ns

  pub fn get_stats(&self) -> IntrusionStats
    Get comprehensive statistics: failed_attempts, blocked_ips,
    block_rate_ppm, FPR estimate, etc.
    Latency: <100ns

  pub fn estimate_fpr(&self) -> f64
    Calculate current false positive rate based on items inserted.
    Formula: (1 - e^(-k*n/m))^k
    Latency: <20ns

  pub fn reset(&self)
    Hard reset all Bloom bits and counters. Use for maintenance.
    Latency: ~10μs (O(n) sequential stores)

STATISTICS:

  pub struct IntrusionStats {
      pub failed_attempts: u64,          // Total failures
      pub blocked_ips: u64,              // Unique IPs estimate
      pub false_positive_estimate: u64,  // FPR in ppm
      pub total_checks: u64,             // Total checks
      pub checks_passed: u64,            // Allowed checks
      pub checks_blocked: u64,           // Denied checks
      pub block_rate_ppm: u64,           // Blocks/million
  }

ERROR TYPES:

================================================================================
                           KNOWN LIMITATIONS
================================================================================

1. False Positive Rate Degradation
   - FPR increases beyond 50K items (exceeds 0.1% target)
   - Recommendation: Rotate to fresh Bloom filter every 15 min
   - Future: Implement rotating window with multiple buffers

2. Unblock False Negatives
   - Clearing bits may cause legitimate IPs to be incorrectly allowed
   - Scenario: IP A and IP B collide on bit positions
   - Mitigation: Document in appeal process, limited manual unblocks

3. No Distributed Tracking
   - Current: Per-server Bloom filter only
   - Gap: Load-balanced clusters see different state per server
   - Future: Redis/memcached shared backend

4. Latency Overhead
   - 105 ns/op vs 50 ns target (includes atomic accounting)
   - Acceptable for <100μs overall request budgets
   - Future: SIMD vectorization (nightly portable_simd) for 2-3× speedup

5. IP Spoofing
   - Out of scope: Network-level IP spoofing not detectable
   - Assumption: Trusting IP from request headers
   - Mitigation: Deploy behind trusted reverse proxy
