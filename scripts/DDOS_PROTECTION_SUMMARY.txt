PROTECTION LAYERS DEPLOYED
================================================================================

✅ LAYER 1: KERNEL SYN FLOOD PROTECTION
   - tcp_syncookies=1 (stateless defense)
   - tcp_max_syn_backlog=8192 (8x default)
   - tcp_synack_retries=2 (aggressive timeout)
   Resistance: 10,000+ SYN/sec

✅ LAYER 2: CONNECTION TRACKING (netfilter)
   - nf_conntrack_max=1,000,000 (1M capacity)
   - Established timeout: 600s (10 min idle)
   - TIME_WAIT timeout: 60s (aggressive cleanup)
   Resistance: 100K+ concurrent connections

✅ LAYER 3: PER-IP RATE LIMITING (iptables)
   - HTTPS (443): 100 new connections/min per IP
   - HTTP (80): 200 new connections/min per IP
   - Mechanism: iptables 'recent' module
   Resistance: Single-IP DDoS amplification

✅ LAYER 4: MALFORMED PACKET FILTERING
   - NULL packets (no flags): Dropped
   - XMAS packets (all flags): Dropped
   - SYN+FIN combo: Dropped
   - Invalid state: Dropped
   Resistance: Slowloris, half-open attacks

✅ LAYER 5: ICMP RATE LIMITING
   - icmp_ratelimit=100/sec
   - Rate-limit timestamp + time-exceeded
   Resistance: Ping floods, network scanning

✅ LAYER 6: PERSISTENCE & AUTOMATION
   - sysctl config: /etc/sysctl.d/99-ddos-protection.conf
   - iptables rules: Managed by netfilter-persistent
   - Both survive kernel/system reboot

================================================================================
KNOWN ISSUES & SOLUTIONS
================================================================================

ISSUE 1: "Too many open files"
  CAUSE: ulimit too low
  SOLUTION: 
    ulimit -n 65536
    Add to /etc/security/limits.conf: * soft nofile 65536

ISSUE 2: "Cannot assign requested address"
  CAUSE: TCP TIME_WAIT exhaustion
  SOLUTION:
    Verify: sysctl -n net.ipv4.tcp_tw_reuse (should be 1)
    Monitor: ss -tan | grep TIME_WAIT | wc -l

ISSUE 3: "Legitimate traffic rate-limited"
  CAUSE: Limit too aggressive
  SOLUTION:
    Check: sudo iptables -L INPUT -n -v | grep "hitcount:"
    Increase limit (example: HTTPS from 100 to 200/min)
    Save: sudo netfilter-persistent save

ISSUE 4: "kernel: nf_conntrack: table full, dropping packet"
  CAUSE: conntrack memory exhausted
  SOLUTION:
    sudo sysctl -w net.netfilter.nf_conntrack_max=2000000
    Add to /etc/sysctl.d/99-ddos-protection.conf
    sudo sysctl -p
