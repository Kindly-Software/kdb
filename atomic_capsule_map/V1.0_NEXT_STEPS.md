### Day 3-4: P0-2 - Fix Concurrent Resize (CRITICAL - 8-16 hours)

#### Current Failure
```
test table::tests::table_resize_concurrent_operations ... FAILED
thread panicked: called `Result::unwrap()` on an `Err` value: ()
Location: src/table.rs:897:56
```

#### Root Cause Analysis
- Incomplete atomic coordination during resize
- Buckets not properly synchronized
- Race condition in bucket allocation
- Generation counters insufficient

#### Fix Approach
1. **Read The Atomic Capsule** (two-phase commit for resize)
2. **Redesign resize protocol**:
   - Use generation counter for resize coordination
   - Atomic transition between old/new buckets
   - Readers see consistent view during resize
3. **Remove `unwrap()`** in hot paths (ASSUM PANIC_SAFETY)
4. **Test under concurrent load**
