ARCHITECTURE OVERVIEW
================================================================================

SessionCapsule Layout (256 bytes):
├── state: DualAtomicU64 (128 bytes)
│   ├── Primary (offset 0-7): session_id (0 = invalid)
│   ├── Padding (offset 8-63): 56 bytes
│   ├── Secondary (offset 64-71): expiry_unix
│   └── Padding (offset 72-127): 56 bytes
├── created_unix: AtomicU64 (8 bytes)
├── last_activity: AtomicU64 (8 bytes)
├── generation: AtomicU64 (8 bytes)
└── _padding: [u8; 88] (88 bytes)

State Machine:
1. New() → Uninitialized (session_id = 0)
2. Create() → Active (session_id = non-zero)
3. Extend() → Extended (expiry increased, generation++)
4. Invalidate() → Destroyed (session_id = 0, generation++)

TOCTOU Prevention:
- Generation counter increments on every mutation
- Readers can detect concurrent modifications
- is_valid_consistent() checks generation before/after read

Audit Trail (Q34):
- created_unix: Immutable creation timestamp
- last_activity: Activity tracking
- generation: Mutation counter (hash-chain)
- expiry_unix: Expiration timestamp
