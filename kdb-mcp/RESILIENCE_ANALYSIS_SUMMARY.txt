DETAILED FAILURE MODES BY CATEGORY
================================================================================

CATEGORY 1: CATASTROPHIC FAILURES
  Failure Mode 1.1: Server Crash (Panic/Segfault)
    - 4 specific gaps identified
    - Root causes: Unsafe deref, integer overflow, unwrap panic, TOCTOU race
    - Recovery: Auto-restart via systemd (5-15s downtime)
    - Fix: Schema validation, clock monotonicity, safe error handling

  Failure Mode 1.2: Kernel Panic / OOM Killer
    - 3 specific gaps identified  
    - Root causes: Unbounded allocations, no memory limits, no cleanup
    - Recovery: systemd restarts, but cascading failures possible
    - Fix: Memory budgeting, cgroup limits, cleanup on connection close

  Failure Mode 1.3: Disk Full During Critical Operation
    - 3 specific gaps identified
    - Root causes: No pre-check, non-atomic writes, unbounded logs
    - Recovery: Manual intervention or graceful degradation
    - Fix: Pre-flight checks, atomic writes, logrotate

CATEGORY 2: GRACEFUL DEGRADATION
  Failure Mode 2.1: Missing Circuit Breaker for Debugger
    - Debugger failures not tracked
    - No backoff/retry policy
    - Clients waste resources retrying immediately
    - Fix: Implement circuit breaker (5 failures = 30s timeout)

CATEGORY 3: RESOURCE EXHAUSTION ATTACKS
  Failure Mode 3.1: Unbounded Concurrent Connections
    - No per-client connection limit check
    - 10K connections = 40MB memory consumed
    - Thread pool exhaustion possible
    - Fix: Add ConnectionPoolManager (max 1000 concurrent)

CATEGORY 4: NETWORK FAILURES
  Failure Mode 4.1: Hung Socket Read/Write
    - No timeouts on stdio operations
    - Event loop blocks indefinitely if parent dies
    - No keepalive heartbeat
    - Fix: Add read (30s) / write (10s) timeouts, keepalive heartbeat

  Failure Mode 4.2: DNS Failures (if using hostnames)
    - No DNS caching
    - No fallback on resolution failure
    - Fix: Add DNS cache with TTL, fallback to stale entries

CATEGORY 5: DATA CORRUPTION
  Failure Mode 5.1: Incomplete Audit Trail Writes
    - Ring buffer write not atomic across index update
    - Crash between copy and index update = data loss
    - Hash chain broken = Q34 compliance invalid
    - Fix: Atomic write with copy-before-publish pattern, memory fence

CATEGORY 6: UPGRADE FAILURES
  Failure Mode 6.1: Binary Incompatibility
    - No version field in checkpoint format
    - Old checkpoints can't be parsed after upgrade
    - Cascading failure during rollback
    - Fix: Add version prefix to checkpoints, validation on load

CATEGORY 7: OPERATIONAL ERRORS
  Failure Mode 7.1: Misconfiguration (Missing Config File)
    - No config file schema validation
    - Missing config.toml = uses unsafe defaults
    - No alert about missing file
    - Fix: Config schema validation, require config file

CATEGORY 8: UNSAFE BLOCKS
  - Total unsafe blocks: 39
  - Documented assumptions: 24 blocks
  - Undocumented risks: 5 blocks (HIGH RISK)
  - Medium risk issues: 10 blocks

  High-Risk Unsafe Blocks:
    1. Ring buffer UnsafeCell access without TOCTOU protection
    2. Pointer arithmetic in stdio_transport without bounds
    3. NaN handling in anomaly_detector with unwrap
    4. Time operations with unwrap on SystemTime failure
    5. Buffer access without index validation

  Fix: Add #ASSUME and #VERIFY tags, bounds validation, safe wrappers

CATEGORY 9: ATOMIC ORDERING INCONSISTENCIES
  - Mix of Relaxed/Acquire/Release without clear rules
  - Acquire on load + Release on store (correct)
  - But: Relaxed on metrics updates (race condition)
  - TOCTOU race in ring buffer wraparound detection
  - Fix: Establish clear ordering rules, audit all atomic ops
