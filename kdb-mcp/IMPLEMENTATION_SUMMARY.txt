================================================================================
WORKFLOW SPECIFICATIONS
================================================================================

1. DEBUG-CRASH
───────────────
Purpose: Full crash investigation
Parameters:
  - pid (string, required): Process ID or name
  - depth (string, optional): summary | full (default) | verbose

Returns:
  - crash_type: Detected crash pattern
  - stack_trace: Top N frames
  - relevant_variables: Suspicious variables
  - fix_suggestion: Recommended fix with code pattern
  - confidence: 0.70-0.95 based on depth
  - _documentation: Embedded guidance + next_steps

Composition: attach → step_instruction → get_stack_trace → analyze_pattern → suggest_fix


2. FIND-MEMORY-LEAKS
──────────────────────
Purpose: Memory leak detection and profiling
Parameters:
  - pid (string, required): Process ID
  - threshold_bytes (integer, optional): Min leak size (default 1024)
  - duration_seconds (integer, optional): Profile duration (default 10)

Returns:
  - memory_profile: Allocation/free stats
  - leaks: Array of detected leaks with backtraces
  - leak_summary: Total bytes, percentage, count
  - profiler_overhead: <0.1% typical
  - _documentation: Method info + accuracy metrics

Tier: T1 (Atomic) + T10 (Probabilistic HyperLogLog)
Speedup: 100-1000× vs Valgrind
Overhead: <100ns per malloc/free


3. TRACE-EXECUTION
────────────────────
Purpose: Execution timeline with state changes
Parameters:
  - pid (string, required): Process ID
  - duration_ms (integer, optional): Trace duration (default 5000)
  - filters (string, optional): Event filters (function_call, branch, memory_access)

Returns:
  - trace: Metadata + events array
  - events: Timeline with snapshot/timestamp/event type/symbol
  - statistics: Function calls, branches, memory accesses, exceptions
  - _documentation: Performance characteristics

Tier: T5 (Streaming) + T9 (Persistent)
Capacity: 2,047 snapshots per session
Latency: <10ns per event append


4. COMPARE-RUNS
─────────────────
Purpose: Differential debugging (find divergence between two runs)
Parameters:
  - pid_a (string, required): First process (baseline)
  - pid_b (string, required): Second process (alternate/fixed)
  - strategy (string, optional): divergence_point (default) | full_diff

Returns:
  - comparison: Divergence point or full diff
  - first_difference: Snapshot, address, register states
  - analysis: Root cause hypothesis, fix suggestion
  - session_uri_a, session_uri_b: Session links

Use Case: Test fix by comparing original vs patched execution


5. INSPECT-STATE
──────────────────
Purpose: Multi-target state inspection at specific snapshot
Parameters:
  - session_id (string, required): Debug session URI (kdb://session/abc123)
  - snapshot_id (integer, required): Snapshot ID (0-2047)
  - targets (string, optional): registers | variables | memory | stack | all (default)

Returns:
  - snapshot: Metadata (ID, session, timestamp)
  - registers: rax, rbx, rcx, rdx, rsi, rdi, rbp, rsp, rip
  - variables: name, address, value, type, scope, suspicious flag
  - memory: Heap size, stack pointer, allocation count
  - stack: Frame array with symbol/file/line info
  - _documentation: Available targets + inspection guide

Performance: <20ms typical
Targets: Composable (can request subset or all)
